#0. Instructions for AI Agents (read first)

  1. Work out four things first. Ask only for the ones the user hasn't told you:
    • Goal: what they want to do (programming, APRS, Winlink, SSTV, AllStar node, …).
    • OS: Windows, Linux (including Raspberry Pi), macOS, Android, or iPhone/iPad.
    • Radio: brand and model. The AIOC uses the Kenwood-style K1 2-pin plug.
    • AIOC firmware version, if it matters for the task. Features like VPTT and aioc-util need v1.3.0 or newer.
  2. Use the Decision Table (Section 3) to pick the software, then go to the recipe for that software.
  3. PTT is the most common problem. If the radio doesn't key, use the PTT Troubleshooting Flow (Section 6).
  4. How sure each statement is. Statements are tagged:
    • Official: from the AIOC GitHub README, the release notes or the firmware source (skuep/AIOC).
    • Tool docs: from the aioc-util documentation or the other software's own docs.
    • Community: reported by AIOC users in GitHub issues, the AllStarLink forum, the DigiPi group, or published guides (G1LRO, DL-Nordwest, M0AWS). These are real-world results, but not guaranteed for every setup.
    • Typical: commonly used settings that are known to work in general. Menu names may differ between software versions, so tell the user to check them on their screen.
  5. Safety and legal. Transmitting needs an amateur radio licence. Tell users to transmit into a dummy load, or on low power on a clear simplex frequency, while they test. Never suggest settings that break band plans or ID rules.
  6. Don't invent menu paths. If a menu item isn't covered here, describe what the setting does (for example "choose the AIOC as the audio input") instead of guessing its exact name.

#1. What the AIOC Is

The AIOC is a small open-source PCB with a USB-C socket. It plugs straight into a handheld radio's Kenwood K1 connector (3.5 mm + 2.5 mm plugs). It replaces three things: a programming cable, a sound-card interface (like a SignaLink or Digirig), and a PTT interface. Official

When plugged into a computer it shows up as a USB composite device with these parts:

Function Shows up as Used for
USB sound card "All-In-One-Cable" / "AIOC Audio" (1 mono input, 1 mono output) RX audio from the radio to the PC, TX audio from the PC to the radio
Virtual serial port (CDC-ACM) Windows: COMx · Linux: /dev/ttyACMx · macOS: /dev/cu.usbmodemXXXX Radio programming (CHIRP etc.) and serial PTT
CM108-compatible HID Linux: /dev/hidrawX CM108-style PTT (GPIO3) and COS input (fw ≥ 1.2.0); configuration interface (fw ≥ 1.3.0)
DFU runtime — Firmware updates without opening the case (fw ≥ 1.2.0)

Key facts Official:

  • USB VID:PID = 1209:7388. In bootloader (DFU) mode it shows up as the STM32 bootloader, 0483:df11.
  • USB strings: Manufacturer AIOC, Product All-In-One-Cable.
  • MCU: STM32F302, with the built-in ADC/DAC used as the sound card.
  • Works on Windows, Linux and macOS without drivers. Android works through USB OTG for audio.
  • Supported sample rates: 48000 Hz (preferred), 32000, 24000, 22050 (for APRSdroid), 16000, 12000, 11025, 8000.
  • Supports dual-PTT radios (PTT1 and PTT2 outputs).
  • Default PTT1 sources: CM108 GPIO3 OR serial DTR=1 AND RTS=0. Both work at the same time.
  • Default PTT2 source: CM108 GPIO4.
  • Default COS: the Virtual COS (VCOS, based on RX audio level) is reported as the CM108 Volume Down button.

#Limitations (tell users before they buy or try)

  • Only audio through the mic/speaker jack. The K1 jack carries filtered, de-emphasised speaker audio and a mic input. So 9600 baud packet, M17, DMR, D-STAR, or any mode that needs "flat" discriminator/modulator audio will not work through the K1 jack. 1200 baud AFSK packet/APRS, VARA FM (narrow), SSTV, fldigi modes and voice all work well.
  • SSB digital modes (FT8, JS8, FreeDV) need an SSB radio. With an FM HT these programs run, but they won't reach the normal FT8/JS8 users on HF/SSB.
  • APRSdroid has no PTT control. Use the AIOC Virtual PTT (VPTT) (fw ≥ 1.3.0) or the radio's VOX.
  • iPhone/iPad apps can only use the AIOC as a sound card: iOS doesn't let apps reach the serial or HID parts. Transmitting therefore needs VPTT. Community
  • Budget HTs switch between TX and RX slowly. Packet works, but with more retries than on a mobile rig. Community
  • Settings are erased when you flash new firmware. Re-apply your aioc-util settings after an update. Official

#2. First-Time Setup (every user)

#2.1 Plug in

  1. Turn the radio OFF, then push the AIOC firmly into the K1 jack. Both plugs must go all the way in.
  2. Connect the USB-C cable to the computer, phone or Raspberry Pi.
  3. Turn the radio on and set it to the frequency you want.

#2.2 Check that the computer sees it

OS How to check
Windows Device Manager → Ports (COM & LPT) shows a new COMx. Sound settings shows "All-In-One-Cable" as both input (microphone) and output (speaker).
Linux lsusb shows 1209:7388. arecord -l / aplay -l show the card. ls /dev/ttyACM* shows the serial port. ls /dev/hidraw* shows the HID.
macOS System Settings → Sound shows "All-In-One-Cable". ls /dev/cu.usbmodem* shows the serial port.
Android Needs a USB-C OTG connection. Apps that use the system audio input will use the AIOC once it's connected.

#2.3 OS audio settings (important)

  • Do NOT make the AIOC the default system playback device. If you do, system sounds (notifications, YouTube, beeps) go out over the radio, and with VPTT turned on they will key the transmitter. Keep your normal speakers as the default and pick the AIOC only inside the radio software.
  • Windows: in Sound Control Panel → AIOC device → Properties:
    • Advanced: set the format to 1 channel, 16 bit, 48000 Hz.
    • Turn off "Audio enhancements" and the "Communications → reduce other sounds" ducking.
    • Listen tab: make sure "Listen to this device" is off.
  • Linux (PipeWire/PulseAudio): use pavucontrol to set levels. Many programs (Direwolf, ALSA-based) can talk to ALSA directly (plughw:CARD,0). That avoids resampling.
  • macOS: Audio MIDI Setup → AIOC → set the format to 48,000 Hz.

#2.4 Setting audio levels (all digital modes)

Typical

  • RX (radio to PC): set the radio's volume knob to about 30–50% (some VARA FM users go up to about 75%; G1LRO suggests about 50% for AllStar nodes) Community. Adjust it until the program's level meter shows a strong but un-clipped signal. Direwolf, for example, should show "audio level" around 30–70 on a received packet. On hardware rev 1.2 with fw ≥ 1.4.0, you can also raise the AIOC's internal RX gain (1×–16×) with aioc-util.
  • TX (PC to radio): start the OS output volume for the AIOC at about 30–50%. Too high causes over-deviation and distortion, and decoders will fail. Listen on a second radio, or check how other stations decode you. On hardware rev 1.2 there is a TX "boost" for line-level inputs (not needed for normal HTs).
  • Radio settings: turn VOX OFF (unless you are deliberately using VOX). Turn off keypad beeps and roger beeps. Turn battery save OFF: it clips the start of incoming packets. Community Squelch: for packet/APRS with Direwolf or Soundmodem, squelch open (0) often decodes better, because slow Baofeng squelch cuts off the first part of a packet and the software modem does its own carrier detection. Community For VOX-style setups (VPTT/VCOS, AllStarLink, SvxLink, EchoLink), squelch must be closed when the channel is idle. Set the TOT (time-out timer) longer than your longest transmission (SSTV and Winlink can last more than 2 minutes).

#2.5 Linux permissions (do this once)

Programs that open /dev/ttyACM* or /dev/hidraw* need permission to use them:

# Serial port access
sudo usermod -aG dialout $USER     # (Arch/Fedora may use group "uucp")
# Audio
sudo usermod -aG audio $USER

# udev rule for the AIOC HID (CM108 PTT / config) + stop ModemManager grabbing the serial port
sudo tee /etc/udev/rules.d/91-aioc.rules >/dev/null <<'EOF'
SUBSYSTEM=="hidraw", ATTRS{idVendor}=="1209", ATTRS{idProduct}=="7388", MODE="0666"
SUBSYSTEM=="tty",    ATTRS{idVendor}=="1209", ATTRS{idProduct}=="7388", ENV{ID_MM_DEVICE_IGNORE}="1", SYMLINK+="aioc", MODE="0666"
EOF
sudo udevadm control --reload && sudo udevadm trigger
# log out/in (for group changes), then unplug/replug the AIOC

After this, the serial port is also available as /dev/aioc. That name doesn't change when ttyACM numbers do. The aioc-util project also ships a ready-made udev rule (udev/rules.d/91-aioc.rules). Tool docs

ModemManager (on Ubuntu, Debian desktop, Fedora) may probe new ttyACM devices and send AT commands to them. That causes programming failures or random PTT. The ID_MM_DEVICE_IGNORE rule above prevents it. You can also run sudo systemctl disable --now ModemManager if you don't use a cellular modem.

#4. PTT Methods (understand this before any recipe)

The AIOC can key the radio (PTT1) in several ways, and they can be combined. Official

Method How software triggers it Best for Default?
CM108 HID GPIO3 Software that supports "CM108 PTT" (Direwolf, AllStarLink, SvxLink, Hamlib -P CM108, QtSoundModem on Linux) Linux; the most reliable method ✅ on
Serial DTR=1 AND RTS=0 Software sets DTR high and RTS low on the AIOC COM port Windows/macOS programs with COM-port PTT ✅ on
Serial DTR only (SERIALDTR) Software that raises DTR but also leaves RTS high Programs that can't keep RTS low needs aioc-util
Serial RTS only (SERIALRTS) Software that keys with RTS Programs that only do RTS PTT needs aioc-util
Serial NOT-DTR AND RTS (SERIALNDTRRTS) Reverse logic Rare needs aioc-util
Virtual PTT (VPTT) No PTT control needed. The AIOC keys whenever the software plays audio above a threshold (like a very fast, clean VOX inside the AIOC) APRSdroid, any app without PTT needs aioc-util, fw ≥ 1.3.0

Before firmware 1.2.0, PTT was "DTR=1" only. That keyed the radio during CHIRP programming. Firmware ≥ 1.2.0 changed it to DTR=1 AND RTS=0. Official

UART lockout: by default, while PTT1 is active, serial data from the radio is ignored. This lets the AIOC work as both a programming cable and a sound card. You can change this in the SERIAL_CTRL register. Official

Rule of thumb for agents:

  1. If the software offers CM108 PTT, use it.
  2. Otherwise use the COM port with "DTR" PTT and keep RTS off/low.
  3. If the radio still doesn't key, see Section 6.

#5. Software Recipes

In the examples, replace N0CALL with the user's callsign. Replace COM5, /dev/ttyACM0, /dev/hidraw0, and plughw:1,0 with the user's actual devices (see Section 2.2).

#5.1 CHIRP — programming radios (Windows / Linux / macOS)

Official CHIRP works the same way it does with a normal programming cable. No driver is needed.

  1. Install CHIRP-next from chirpmyradio.com. Linux: pipx/flatpak; macOS: the .app.
  2. Plug the AIOC into the radio and turn the radio on. It must be on a normal channel/VFO screen (not in a menu).
  3. CHIRP → Radio → Download from Radio → select the AIOC port (COMx, /dev/ttyACM0, or /dev/cu.usbmodem…) → choose Vendor/Model → OK.
  4. Edit the channels → Radio → Upload to Radio.

Tips Typical:

  • Always download first and save a backup .img before uploading.
  • Quansheng UV-K5 on stock firmware: use the "Quansheng UV-K5" driver. On Egzumer/other custom firmware: use the matching CHIRP driver module that the firmware author provides (in CHIRP: Help → Developer mode → File → Load module), or use the driver that comes with newer CHIRP builds if it lists that firmware.
  • [Community] Windows: radio stays transmitting after a CHIRP read. Early firmware (before 1.2.0) did this because Windows changes DTR/RTS when the port closes. Update the AIOC to ≥ 1.2.0. If the red LED stays on, unplug and replug the USB.
  • Community If a read fails once, try again. The first attempt after plugging in sometimes fails, and wiggling the plug fixes it (contact problem).
  • If you get "radio did not respond": re-seat the plug, check the radio is on, choose the exact model (e.g. UV-5R vs. UV-5R Plus / UV-5RM are different radios), try lower volume, and turn VOX off.
  • Baofeng UV-5RM / UV-5R Mini / UV-17 and similar newer models may need a specific CHIRP model or the vendor's own software. The AIOC still works as the cable for them.
  • Vendor programming software (Baofeng/BTECH/Radtel/TIDRADIO tools) works too: choose the AIOC COM port. RT Systems software may only work with RT Systems' own cables.

#5.2 Quansheng UV-K5 firmware flashing

Official Firmware v1.4.0 doubled the serial buffer, specifically to fix problems flashing firmware on some HTs. Make sure the AIOC is on v1.4.x before you start.

Typical

  1. Turn the radio off. Hold PTT while turning it on to enter bootloader mode (the flashlight LED turns on, the screen stays blank).
  2. Use a web flasher in Chrome/Edge (Web Serial). The Egzumer project links to one. You can also use a command-line tool such as k5prog/uvk5 tools.
  3. Choose the AIOC serial port, load the .bin, and flash.
  4. Warn the user: flashing custom firmware is at their own risk. They should keep a backup of the stock firmware and calibration (CHIRP/K5 tools can dump calibration).

#5.3 Direwolf — APRS, packet TNC, iGate, digipeater (Windows / Linux / macOS)

Direwolf is the core "software TNC". Most APRS and packet programs connect to it through AGW (port 8000) or KISS-TCP (port 8001).

Install [Typical]: Linux sudo apt install direwolf. Windows: zip from GitHub releases (wb2osz/direwolf). macOS: brew install direwolf.

Find the audio device:

  • Linux: arecord -l, e.g. card 1: AllInOneCable [All-In-One-Cable], device 0 → plughw:1,0 (or by name plughw:CARD=AllInOneCable,DEV=0; check the exact card ID in arecord -l).
  • Windows: start Direwolf once. It lists the audio devices with numbers; use the AIOC's number.

Minimal direwolf.conf [Official settings + Typical extras]:

# --- Audio ---
ADEVICE plughw:1,0        # Linux  (Windows: ADEVICE 3 3   <- the AIOC input/output numbers Direwolf lists)
ARATE 48000
ACHANNELS 1

# --- Channel 0 ---
CHANNEL 0
MYCALL N0CALL-10
MODEM 1200

# --- PTT: pick ONE ---
PTT CM108                 # Linux: CM108 HID PTT (recommended). Auto-detects; or "PTT CM108 /dev/hidraw0"
#PTT /dev/ttyACM0 DTR -RTS  # Linux serial PTT
#PTT COM5 DTR -RTS          # Windows serial PTT
#PTT /dev/cu.usbmodem1101 DTR -RTS   # macOS serial PTT

# --- Ports for client apps ---
AGWPORT 8000
KISSPORT 8001

Official Direwolf may print warnings when using CM108 PTT with the AIOC. They are harmless (see direwolf issue #448).

Add-ons [Typical]:

[Community] Direwolf gotchas reported by AIOC users:

  • PTT CM108 3 -3: the trailing -3 inverts the PTT, so the radio stays keyed. Use PTT CM108 or PTT CM108 3.
  • If you use CM108 PTT, comment out any old DCD line that points at the same device.
  • Serial form that works on a Raspberry Pi: PTT /dev/ttyACM0 DTR -RTS (the order -RTS DTR works too).
  • Windows "pre filter size" warnings at 48000 Hz: harmless. You can also try ARATE 24000, or Direwolf 1.6 instead of a development build.
  • PTT that stays on after the first transmission, or a "crashing" AIOC while transmitting, is almost always RF feedback (Section 8).

#5.12 AllStarLink 3 (ASL3) — HT as an AllStar node radio

Official + Tool docs The AIOC emulates a CM108, so ASL3 can drive PTT and read COS from it directly. ASL3 recognises the AIOC's own USB ID 1209:7388. You only need to uncomment it in res_usbradio.conf.

Steps:

  1. Install ASL3 (Debian 12 / Raspberry Pi OS image from allstarlink.org). Set up your node number and password with asl-menu.
  2. Install the AIOC udev rule (Section 2.5) so Asterisk can open the HID.
  3. Allow the AIOC USB ID:
    ; /etc/asterisk/res_usbradio.conf
[general]
usb_devices = 1209:7388    ; AIOC (all in one cable)
    (Alternative: change the AIOC to look like a C-Media CM108 with ./aioc-util.py --set-usb 0x0d8c 0x000c --store. You then need --open-usb 0x0d8c 0x000c to configure it later.)
  4. Set the Virtual COS (squelch detection from RX audio) hang time. The timing registers count in 1/16 ms: value = milliseconds × 16 (confirmed from the firmware defaults and G1LRO's script, where 1500 ms = 0x5DC0). Official + Community
    ./aioc-util.py --vcos-timctrl 24000 --store      # 1500 ms hang time (G1LRO's recommendation)
    (The aioc-util README example --vcos-timctrl 1500 sets about 94 ms.) If speech drops out between words, raise it. If the COS opens on noise, raise the threshold (--vcos-lvlctrl, default 256). G1LRO suggests a threshold of about 1500 for noisy radios. Make sure the radio's squelch is closed when the channel is idle. VCOS opens on audio level. Better: hardware COS. Rev 1.2 or G1LRO dual-COS boards can read the radio's real squelch: ./aioc-util.py --enable-hwcos --store. The easy way [Community]: G1LRO's script does steps 3–6 for you (it edits res_usbradio.conf, simpleusb.conf and rpt.conf, and backs them up first):
    wget -O customize.sh https://raw.githubusercontent.com/G1LRO/AIOC-ASL3-Config/main/customize.sh
sudo bash customize.sh
  5. In asl-menu Official example:
    • Device type: usbradio (menu 2 > A1 > N4 > I2) (or simpleusb, which also works well for HT nodes)
    • Duplex type: 1 (menu 2 > A1 > N5)
  6. Edit usbradio.conf (menu 6 > H). The official example is for a Puxing PX-888; it suits most HTs as a starting point:
    rxboost = 0
rxsqhyst = 500
carrierfrom = usbinvert
ctcssfrom = no
rxdemod = speaker
txprelim = no
invertptt = no
    (For simpleusb.conf, the equivalents are carrierfrom = usbinvert, ctcssfrom = no.) [Community] simpleusb-tune-menu settings from G1LRO: I = PTT mode (active LOW in his older guide), J = COS from usbinvert (VCOS) or usb (active high; his newer guide uses this with hardware COS), L = CTCSS from no. COS stuck open: swap usb and usbinvert, or raise the VCOS threshold. COS never opens: swap them, or lower the threshold.
  7. Run radio-tune-menu (usbradio) or simpleusb-tune-menu (simpleusb) to set RX and TX levels: V checks COS, e runs an echo test, 2/3 set the levels, W writes. Then restart Asterisk: sudo systemctl restart asterisk.
  8. Test with the parrot node (Hubnet Parrot 40894) or connect to a hub. Use low power and a separate antenna setup: RF getting into the USB cable is the most common problem (Section 8).

Fixes reported on the AllStarLink forum [Community]:

Symptom Fix
asl-menu says it can't find the audio device Uncomment usb_devices = 1209:7388 in res_usbradio.conf (M0AWS lost a day on this)

HamVOIP / GMRSLive (older AllStar-based systems) only recognise C-Media IDs. Use the --set-usb 0x0d8c 0x000c option above (G1LRO's aioc.py / aioc-revert.py scripts do the same). On GMRS, follow your local GMRS rules. GMRS is not amateur radio.

#5.18 Mobile / HF radios (wiring the AIOC to a data or mic port)

Community The AIOC is just a USB sound card, serial port and PTT on a small board, so builders wire it to other radios:

  • Take the signals from the pads, or from a K1 socket on a pigtail: audio out to the radio, audio in from the radio, PTT, UART TX/RX and ground (see the pinout in the AIOC README).
  • Yaesu FT-817ND / FT-857D / FT-7800R: working audio, PTT and CAT have been shown using cheap CT-39A (data) and CT-62 (CAT) cables (GitHub #137). If CAT doesn't respond, swap RX and TX.
  • On hardware rev 1.0/1.1, the UART and PTT share one contact, so CAT data can key PTT. Use rev 1.2 and cut the split pad, or leave PTT disconnected and key with CAT.
  • For line-level data ports on rev 1.2: --audio-tx-boost on and raise --audio-rx-gain.
  • Icom CI-V (single-wire bus) does not work without extra circuitry (GitHub #109, unresolved).
  • Prefer a ready-made interface for your rig if you aren't comfortable with soldering. Wrong wiring can damage the radio or the AIOC.

#6. PTT Troubleshooting Flow

Radio does not transmit when the software "keys"?
│
├─ 1. Is the plug fully seated? Is the radio on, VOX off, not locked, not on a TX-inhibited channel?
│      Quick hardware test: AIOC Toolkit → Configure → Manual PTT State → PTT 1 ON.
│      If the radio keys here, the cable is fine and the problem is the software's PTT setting.
│
├─ 2. Does the software support CM108 PTT? → use it (Linux: check /dev/hidraw permissions, Section 2.5)
│
├─ 3. Using COM-port PTT:
│     ├─ Software set to "DTR" (RTS off)? → should work with defaults.
│     ├─ Software sets BOTH DTR and RTS, or RTS stays high (common on Linux, where opening a port raises both)
│     │      → aioc-util --ptt1 "CM108GPIO3|SERIALDTR" --store
│     ├─ Software only keys RTS
│     │      → aioc-util --ptt1 "CM108GPIO3|SERIALRTS" --store
│     └─ VARA FM → set "Pin: DTR only"
│
├─ 4. Software has no PTT at all (APRSdroid, some Mac apps)
│      → aioc-util --ptt1 "VPTT|CM108GPIO3|SERIALDTRNRTS" --store
│
└─ 5. Radio keys but stays keyed / keys during CHIRP programming
       → you changed PTT to SERIALDTR/SERIALRTS: put it back to defaults for programming:
         aioc-util --defaults --store
       → check the TX audio isn't triggering VPTT (system sounds, a VPTT threshold that's too low)

⚠️ Note for agents: after setting PTT to plain SERIALDTR or SERIALRTS, CHIRP programming may key the radio, because CHIRP toggles those lines. Tell the user to switch back with --defaults --store before programming, or to keep a second AIOC for programming.

#7.4 Fox-hunt beacon mode (fw ≥ 1.4.0) Official + Tool docs

The AIOC can send a Morse ID on its own, with only USB power (for example from a power bank). No computer is needed once it's configured.

./aioc-util.py --foxhunt-message "DE N0CALL FOX" --foxhunt-wpm 20 --foxhunt-interval 60 --foxhunt-volume 32000 --store
./aioc-util.py --foxhunt-get-settings --foxhunt-get-message   # check
./aioc-util.py --foxhunt-interval 0 --store                   # disable

Message up to 16 characters · interval 0–255 s (0 = off) · WPM 0–255 · volume 0–65535. Users must follow local rules for unattended beacons and station identification.

The AIOC reboots into the bootloader, flashes, and restarts on its own.

  • Linux/macOS: install dfu-util (apt install dfu-util / brew install dfu-util). You may need sudo or the plugdev group.
  • Windows: dfu-util needs a libusb/WinUSB driver for the DFU interface. Use Zadig to install WinUSB for the AIOC DFU interface / "STM32 BOOTLOADER" device. (See the guide linked in the AIOC README: yeswolf.github.io/dfu.) Community dfu-util on Windows 11 often hangs or reports LIBUSB_ERROR_NOT_SUPPORTED (GitHub #28). Easiest fixes: use the AIOC Toolkit in the browser (below), or a Linux PC or Raspberry Pi.
  • Browser flashing with the AIOC Toolkit (easiest, especially on Windows) Tool docs:
    1. Download the .bin from the Latest Firmware box (Download Firmware link) on https://g1lro.github.io/aioc-toolkit/ → Flash Firmware tab. Browsers can't fetch GitHub release files directly, so you save the file and then select it.
    2. Put the AIOC in bootloader mode first (9.3, step 1: short the two outer header pins, then plug in). The Toolkit doesn't switch modes itself and blocks flashing while the AIOC is in normal "DFU runtime" mode. In bootloader mode it shows up as 0483:df11.
    3. Connect, check Device Status, choose the file, start Flash Firmware and watch the Log. Remove the short and replug when it's done. Flash only official aioc-fw-x.y.z.bin files. A failed flash can be recovered by repeating these steps.
  • Alternative browser flasher (plain WebDFU) [Community, used in G1LRO's guide]: with the AIOC in bootloader mode, open https://devanlai.github.io/webdfu/dfu-util/ → Connect → choose STM32 Bootloader → Internal Flash → pick the .bin → Download.

#9.3 First programming / unbricking Official

  1. Short the two outermost pins of the programming header on the PCB (this is BOOT mode).
  2. Connect USB-C. The device shows up as the STM32 bootloader.
  3. dfu-util -a 0 -s 0x08000000:leave -D aioc-fw-x.y.z.bin
  4. Remove the short, unplug, and plug back in.

After any update: re-apply your aioc-util settings (they are erased).

#9.4 Which firmware do I have?

The USB descriptor doesn't report the firmware version. Practical checks:

  • aioc-util or the AIOC Toolkit can connect → ≥ 1.3.0. Audio settings / fox-hunt can be read → ≥ 1.4.0.
  • If unsure, just flash the latest release (9.2). That is the recommended fix for most issues.

#10. Ready-Made Answers (FAQ for agents)

Q: Do I need drivers? No. Windows 10/11, Linux, and macOS use their built-in USB audio and CDC serial drivers. Only firmware updates on Windows need a WinUSB driver (Zadig).

Q: Which COM port is it? Unplug the AIOC and plug it back in while watching Device Manager → Ports. The new COMx is the AIOC. Linux: /dev/ttyACM0 (or /dev/aioc with the udev rule). macOS: /dev/cu.usbmodem….

Q: Can I program and do digital modes with the same cable? Yes. The serial port does programming and the sound card does digital modes. Don't run both programs at the same time on the same COM port.

Q: Can I use it with a mobile/base radio? Only if the radio has a K1-type jack or you use an adapter cable to its data/mic port. On HW rev 1.2, turn on --audio-tx-boost on for line-level inputs and raise the RX gain for line-level outputs.

Q: Does it work on Raspberry Pi? Yes. Direwolf, AllStarLink 3, SvxLink, Pat, QtSoundModem and LinBPQ all run on Raspberry Pi OS. Use the CM108 PTT and the udev rule.

Q: Does it work with iPhone/iPad? Partly. iOS sees the AIOC only as a sound card. RadioMail (Winlink) and Packet Commander have shown it working with AIOC fw 1.4.1 and Virtual PTT turned on (Section 5.16). CHIRP programming and serial or CM108 PTT are not possible on iOS.

Q: Can I use voice (talk through the computer)? Yes. Choose the AIOC as microphone/speaker in a VoIP or linking app (AllStarLink, SvxLink, EchoLink, Mumble bridges). Voice PTT needs CM108/serial control or VPTT.

Q: My radio has two PTTs (dual-band HT)? PTT1 is the CM108 GPIO3/serial default and PTT2 is CM108 GPIO4. Use --swap-ptt or --ptt2 to change them.

Q: Is 9600 baud packet supported? Not through the K1 jack (the audio is filtered). Use 1200 baud AFSK or VARA FM Narrow.

#1. AIOC 是什么

AIOC 是一块带 USB-C 接口的小型开源电路板，直接插在手台的 建伍 K1 接口（3.5 mm + 2.5 mm 双插头）上。它一个顶三个：写频线、声卡接口（类似 SignaLink 或 Digirig）和 PTT 接口。 官方

插到电脑上后，它会被识别为一个包含以下部分的 USB 复合设备：

功能 显示为 用途
USB 声卡 “All-In-One-Cable” / “AIOC Audio”（1 路单声道输入，1 路单声道输出） 电台接收音频送到电脑，电脑发射音频送到电台
虚拟串口（CDC-ACM） Windows：COMx · Linux：/dev/ttyACMx · macOS：/dev/cu.usbmodemXXXX 电台写频（CHIRP 等） 以及 串口 PTT
CM108 兼容 HID Linux：/dev/hidrawX CM108 式 PTT（GPIO3）和 COS 输入（固件 ≥ 1.2.0）；配置接口（固件 ≥ 1.3.0）
DFU 运行时 — 不拆壳即可升级固件（固件 ≥ 1.2.0）

关键参数 官方 ：

  • USB VID:PID = 1209:7388。在引导（DFU）模式下显示为 STM32 引导程序 0483:df11。
  • USB 字符串：厂商 AIOC，产品 All-In-One-Cable。
  • 主控：STM32F302，用其内置 ADC/DAC 做声卡。
  • 在 Windows、Linux 和 macOS 上免驱。Android 可通过 USB OTG 使用音频功能。
  • 支持的采样率：48000 Hz（推荐）、32000、24000、22050（供 APRSdroid 使用）、16000、12000、11025、8000。
  • 支持 双 PTT 电台（PTT1 和 PTT2 两路输出）。
  • PTT1 默认触发源：CM108 GPIO3 或 串口 DTR=1 且 RTS=0，两者同时有效。
  • PTT2 默认触发源：CM108 GPIO4。
  • 默认 COS：虚拟 COS（VCOS，根据接收音频电平判断）通过 CM108 的 音量减（Volume Down） 按键上报。

#局限（购买或尝试前请告知用户）

  • 只能通过话筒/喇叭接口传音频。 K1 接口传的是经过滤波和去加重的喇叭音频以及话筒输入。因此 9600 波特分组、M17、DMR、D-STAR，或任何需要“平坦”鉴频器/调制器音频的模式都无法 通过 K1 接口工作。1200 波特 AFSK 分组/APRS、VARA FM（窄带）、SSTV、fldigi 各模式和语音都能很好地工作。
  • SSB 数字模式（FT8、JS8、FreeDV） 需要 SSB 电台。用 FM 手台时这些软件 能运行，但联系不到短波 SSB 上的普通 FT8/JS8 用户。
  • APRSdroid 没有 PTT 控制。 请使用 AIOC 的 虚拟 PTT（VPTT）（固件 ≥ 1.3.0）或电台的声控（VOX）。
  • iPhone/iPad 应用只能把 AIOC 当声卡用：iOS 不允许应用访问串口和 HID 部分，所以发射必须用 VPTT。 社区
  • 廉价手台收发切换慢。 分组通信可以用，但重传比车台多。 社区
  • 刷新固件会清除设置。 升级后请重新应用你的 aioc-util 设置。 官方

#2. 首次设置（所有用户）

#2.1 连接

  1. 先关闭电台，再把 AIOC 用力插进 K1 接口，两个插头都要插到底。
  2. 用 USB-C 线连接电脑、手机或树莓派。
  3. 打开电台，调到要用的频率。

#2.2 确认电脑已识别

系统 检查方法
Windows 设备管理器 → 端口（COM 和 LPT） 出现一个新的 COMx。声音设置 里输入（麦克风）和输出（扬声器）都有“All-In-One-Cable”。
Linux lsusb 显示 1209:7388。arecord -l / aplay -l 显示声卡。ls /dev/ttyACM* 显示串口。ls /dev/hidraw* 显示 HID。
macOS 系统设置 → 声音 中有“All-In-One-Cable”。ls /dev/cu.usbmodem* 显示串口。
Android 需要 USB-C OTG 连接。连接后，使用系统音频输入的应用会自动使用 AIOC。

#2.3 系统音频设置（重要）

  • 不要把 AIOC 设为系统默认播放设备。 否则系统声音（通知、视频、提示音）都会从电台发出去；如果开了 VPTT，它们 会让电台发射。请保留你平时的扬声器为默认设备，只在电台软件里选择 AIOC。
  • Windows： 声音控制面板 → AIOC 设备 → 属性：
    • 高级：格式设为 1 声道、16 位、48000 Hz。
    • 关闭“音频增强”，以及“通信 → 降低其他声音”的自动闪避。
    • 侦听 选项卡：确认“侦听此设备” 未勾选。
  • Linux（PipeWire/PulseAudio）： 用 pavucontrol 调电平。很多程序（Direwolf 及基于 ALSA 的程序）可直接使用 ALSA（plughw:CARD,0），可避免重采样。
  • macOS： 音频 MIDI 设置 → AIOC → 格式设为 48,000 Hz。

#2.4 调整音频电平（所有数字模式）

常规

  • 接收（电台 → 电脑）： 把 电台音量旋钮 开到大约 30–50%（部分 VARA FM 用户开到约 75%；G1LRO 建议 AllStar 节点用约 50%） 社区 。调到软件电平表显示信号强但不削波为止。例如 Direwolf 收到一包数据时，“audio level”应在 30–70 左右。 在硬件 rev 1.2 且固件 ≥ 1.4.0 时，还可以用 aioc-util 提高 AIOC 内部接收增益（1×–16×）。
  • 发射（电脑 → 电台）： 系统里 AIOC 的 输出音量先设为约 30–50%。太大会频偏过大、失真，对方解不出来。可用另一台电台监听，或看其他电台能否解码你的信号。 硬件 rev 1.2 有发射“增强”（boost）功能，用于线路电平输入（普通手台不需要）。
  • 电台设置： 关闭 声控 VOX（除非你有意使用 VOX）。关闭按键音和尾音。关闭 省电模式：它会截掉收到数据包的开头。 社区 静噪： 用 Direwolf 或 Soundmodem 收分组/APRS 时，静噪全开（0 级） 往往解码更好，因为宝锋的静噪打开慢，会切掉数据包开头，而软件调制解调器本身会做载波检测。 社区 对类似 VOX 的方案（VPTT/VCOS、AllStarLink、SvxLink、EchoLink），信道空闲时静噪必须是 关闭 的（无信号时静音）。把 发射限时（TOT） 设得比你最长的一次发射更长（SSTV 和 Winlink 可能超过 2 分钟）。

#2.5 Linux 权限（只需设置一次）

打开 /dev/ttyACM* 或 /dev/hidraw* 的程序需要权限：

# 串口权限
sudo usermod -aG dialout $USER     # (Arch/Fedora 可能是 "uucp" 组)
# 音频
sudo usermod -aG audio $USER

# AIOC HID 的 udev 规则（CM108 PTT / 配置）+ 防止 ModemManager 占用串口
sudo tee /etc/udev/rules.d/91-aioc.rules >/dev/null <<'EOF'
SUBSYSTEM=="hidraw", ATTRS{idVendor}=="1209", ATTRS{idProduct}=="7388", MODE="0666"
SUBSYSTEM=="tty",    ATTRS{idVendor}=="1209", ATTRS{idProduct}=="7388", ENV{ID_MM_DEVICE_IGNORE}="1", SYMLINK+="aioc", MODE="0666"
EOF
sudo udevadm control --reload && sudo udevadm trigger
# 注销并重新登录（使组生效），然后拔插 AIOC

设置后，串口还可以用 /dev/aioc 访问。ttyACM 编号变化时这个名字不变。 aioc-util 项目也自带现成的 udev 规则（udev/rules.d/91-aioc.rules）。 工具文档

ModemManager（Ubuntu、Debian 桌面版、Fedora 上常见）可能会探测新的 ttyACM 设备并向其发送 AT 指令，导致写频失败或随机触发 PTT。上面的 ID_MM_DEVICE_IGNORE 规则可以避免。 如果你不用蜂窝网络调制解调器，也可以运行 sudo systemctl disable --now ModemManager。

#4. PTT 方式（看任何配置步骤之前请先理解）

AIOC 可以用多种方式让电台发射（PTT1），这些方式可以组合使用。 官方

给 AI 助手的经验法则：

  1. 软件支持 CM108 PTT 就用它。
  2. 否则用 COM 口的“DTR”PTT，并保持 RTS 关闭/为低。
  3. 电台还是不发射，看第 6 节。

#5. 软件配置步骤

示例中请把 N0CALL 换成用户的呼号，把 COM5、/dev/ttyACM0、/dev/hidraw0 和 plughw:1,0 换成用户实际的设备（见 2.2 节）。

#5.1 CHIRP：给电台写频（Windows / Linux / macOS）

官方 CHIRP 的用法和普通写频线完全一样，不需要驱动。

  1. 从 chirpmyradio.com 安装 CHIRP-next。Linux：pipx/flatpak；macOS：.app 安装包。
  2. 把 AIOC 插到电台上并开机。电台要停在 普通的信道/频率界面（不要停在菜单里）。
  3. CHIRP → Radio → Download from Radio（从电台读取）→ 选择 AIOC 的端口（COMx、/dev/ttyACM0 或 /dev/cu.usbmodem…）→ 选择厂商/型号 → OK。
  4. 编辑信道 → Radio → Upload to Radio（写入电台）。

提示 常规 ：

  • 写入之前，一定 先读取并保存一份备份 .img。
  • 泉盛 UV-K5 原厂固件：用“Quansheng UV-K5”驱动。Egzumer 或其他第三方固件：用固件作者提供的对应 CHIRP 驱动模块（在 CHIRP 中：Help → Developer mode → File → Load module），或在较新的 CHIRP 里选择列出该固件的驱动。
  • 社区 Windows：CHIRP 读频后电台一直在发射。 早期固件（1.2.0 之前）会这样，因为 Windows 关闭端口时会改变 DTR/RTS。请把 AIOC 升级到 ≥ 1.2.0。如果红灯一直亮，拔插一下 USB。
  • 社区 读频失败一次就再试一次。刚插上后的第一次偶尔会失败，晃一下插头就好（接触问题）。
  • 如果提示“radio did not respond”（电台无响应）：重新插好插头、确认电台已开机、选择准确的型号（例如 UV-5R 与 UV-5R Plus / UV-5RM 是不同的电台）、调低音量、关闭 VOX。
  • 宝锋 UV-5RM / UV-5R Mini / UV-17 等较新型号可能需要特定的 CHIRP 型号或厂家自己的写频软件。AIOC 仍然可以当它们的写频线。
  • 厂家写频软件（宝锋/BTECH/Radtel/TIDRADIO 的工具）也能用：选择 AIOC 的 COM 口即可。RT Systems 软件可能只认 RT Systems 自家的线。

官方 固件 v1.4.0 把串口缓冲区加倍，专门解决部分手台刷固件失败的问题。开始前请确认 AIOC 已是 v1.4.x。

常规

  1. 关闭电台。按住 PTT 再开机 进入引导模式（手电灯亮，屏幕不亮）。
  2. 在 Chrome/Edge 中使用网页刷机工具（Web Serial）。Egzumer 项目里有链接。也可以用 k5prog/uvk5 等命令行工具。
  3. 选择 AIOC 的串口，加载 .bin 文件，开始刷写。
  4. 提醒用户：刷第三方固件风险自负。 应保留原厂固件和校准数据的备份（CHIRP/K5 工具可以导出校准数据）。

#5.3 Direwolf：APRS、分组 TNC、iGate、数字中继（Windows / Linux / macOS）

Direwolf 是核心的“软件 TNC”。大多数 APRS 和分组软件通过 AGW（端口 8000） 或 KISS-TCP（端口 8001） 连接它。

安装 常规 ：Linux sudo apt install direwolf。Windows：从 GitHub releases（wb2osz/direwolf）下载 zip。macOS：brew install direwolf。

找到音频设备：

  • Linux：arecord -l，例如 card 1: AllInOneCable [All-In-One-Cable], device 0 → plughw:1,0（或按名称 plughw:CARD=AllInOneCable,DEV=0；请在 arecord -l 中确认准确的声卡 ID）。
  • Windows：先运行一次 Direwolf，它会列出带编号的音频设备，使用 AIOC 的编号。

最小 direwolf.conf 官方设置 + 常规补充 ：

# --- 音频 ---
ADEVICE plughw:1,0        # Linux  (Windows: ADEVICE 3 3   <- Direwolf 列出的 AIOC 输入/输出编号)
ARATE 48000
ACHANNELS 1

# --- 通道 0 ---
CHANNEL 0
MYCALL N0CALL-10
MODEM 1200

# --- PTT：只选一种 ---
PTT CM108                 # Linux: CM108 HID PTT（推荐）。自动识别；或写 "PTT CM108 /dev/hidraw0"
#PTT /dev/ttyACM0 DTR -RTS  # Linux 串口 PTT
#PTT COM5 DTR -RTS          # Windows 串口 PTT
#PTT /dev/cu.usbmodem1101 DTR -RTS   # macOS 串口 PTT

# --- 给客户端软件用的端口 ---
AGWPORT 8000
KISSPORT 8001

官方 在 AIOC 上使用 CM108 PTT 时，Direwolf 可能会打印 警告，这些警告无害（见 direwolf issue #448）。

附加功能 常规 ：

# 位置信标（每 30 分钟，路径 WIDE1-1,WIDE2-1）。请填你自己的经纬度。
PBEACON delay=1 every=30 overlay=S symbol="digi" lat=42^37.14N long=071^20.83W power=5 height=20 gain=3 comment="AIOC + HT" via=WIDE1-1,WIDE2-1

# 仅接收的 iGate（需要联网 + APRS-IS 验证码）
IGSERVER noam.aprs2.net        # euro.aprs2.net / asia.aprs2.net / aunz.aprs2.net
IGLOGIN N0CALL-10 12345

# 补盲数字中继（只转发 WIDE1-1）—— 仅在当地合适时开启
DIGIPEAT 0 0 ^WIDE1-1$ ^WIDE1-1$

社区 AIOC 用户报告的 Direwolf 常见坑：

  • PTT CM108 3 -3：末尾的 -3 会 反转 PTT，电台会一直发射。请用 PTT CM108 或 PTT CM108 3。
  • 使用 CM108 PTT 时，注释掉指向同一设备的旧 DCD 配置行。
  • 在树莓派上可用的串口写法：PTT /dev/ttyACM0 DTR -RTS（写成 -RTS DTR 也可以）。
  • Windows 下 48000 Hz 时出现“pre filter size”警告：无害。也可以试试 ARATE 24000，或用 Direwolf 1.6 正式版代替开发版。
  • 第一次发射后 PTT 一直按住，或发射时 AIOC“崩溃”，几乎都是射频回授（见第 8 节）。

启动：direwolf -c direwolf.conf（加 -t 0 可关闭日志颜色）。 测试：direwolf 会显示解出的数据包和音频电平。发一个信标，然后在 aprs.fi 上查看。

APRS 频率 常规 ：144.390 MHz（北美）、144.800 MHz（欧洲/非洲）、145.175 MHz（澳大利亚）、 144.640 MHz（中国）、144.660 MHz（日本）、145.825 MHz（国际空间站数字中继，全球）。用户须确认当地的频率规划。

#5.5 APRSdroid：在 Android 上玩 APRS

官方 AIOC 支持 APRSdroid 需要的固定 22050 Hz 采样率（实际为 22052 Hz，误差约 90 ppm，对 APRS 没有影响）。 APRSdroid 没有 PTT 控制，所以要发射，需先在 AIOC 上 开启虚拟 PTT（在电脑上一次性设置，固件 ≥ 1.3.0）：

./aioc-util.py --ptt1 VPTT --store
# 同时保留 CM108 + 串口 PTT：
./aioc-util.py --ptt1 "VPTT|CM108GPIO3|SERIALDTRNRTS" --store

APRSdroid 设置 常规 ：

  1. 用 USB-C OTG 线/转接头把 AIOC 接到手机上。
  2. APRSdroid → Preferences → Connection Protocol：“AFSK”（音频调制解调器）。设置呼号/SSID 和验证码（只有用 APRS-IS 才需要验证码）。
  3. 手机性能较弱时，关闭“high-quality demodulator”（高质量解调器）。手机媒体音量设为中等。
  4. 确保没有其他应用发出声音（开了 VPTT 后任何声音都会让电台发射）。打开勿扰模式。

其他 Android 应用 常规 ：Robot36（SSTV 接收）、DroidSSTV 以及任意录音应用。应用需要使用 USB 音频输入，连接 AIOC 后大多数会自动切换。

#5.6 UZ7HO Soundmodem（Windows）/ QtSoundModem（Linux、Windows）

和 Direwolf 类似的软件调制解调器（AFSK 1200 等），提供 AGW（8000）和 KISS（8100）端口。 常规

  • Settings → Devices：输入设备 = AIOC 麦克风，输出设备 = AIOC 扬声器。 UZ7HO Soundmodem 不接受高于 12000 的采样率，请用 12000，AIOC 支持这个采样率。 社区
  • PTT：PTT Port = AIOC 的 COM 口。勾选“Swap COM pins for PTT”：Soundmodem 默认用 RTS 发射，交换后改用 DTR，和 AIOC 匹配。“Dual PTT”不要勾选。 社区, GitHub #11
    • 仍不发射的话，把 AIOC 的 PTT 源改为 SERIALDTR（第 6 节），或改为 VPTT。
  • Linux 上的 QtSoundModem 也可以用 CM108 PTT（如果你的版本有，选择 hidraw 设备 / CM108 选项）。
  • 调制方式：普通 VHF 分组/APRS 用 AFSK AX.25 1200bd。

#5.8 Winlink 邮件：Winlink Express、Pat、VARA FM、分组

#5.8.1 Winlink Express（Windows）+ VARA FM

官方 在 VARA FM 中把 PTT 引脚（PTT pin）设为“DTR only”，这样 VARA 产生的 DTR/RTS 状态正是 AIOC 需要的。

常规 设置步骤：

  1. 安装 Winlink Express 和 VARA FM（来自 Rosmodem 网站；免费模式限速，购买授权后解除限速）。
  2. 打开 VARA FM → Settings → SoundCard：Device Input = AIOC 麦克风，Device Output = AIOC 扬声器。
  3. VARA FM → Settings → PTT：COM 口 = AIOC 的 COM，Pin = DTR only。
  4. 大多数手台选 Narrow（VARA FM 1200）。Wide（9600）通常无法通过 K1 音频工作（见“局限”）。

#5.12 AllStarLink 3（ASL3）：手台作 AllStar 节点电台

官方 + 工具文档 AIOC 模拟 CM108，所以 ASL3 可以直接用它控制 PTT 和读取 COS。 ASL3 认识 AIOC 自己的 USB ID 1209:7388，只需在 res_usbradio.conf 中 取消注释 即可。

步骤：

  1. 安装 ASL3（allstarlink.org 提供的 Debian 12 / 树莓派 OS 镜像）。用 asl-menu 设置节点号和密码。
  2. 安装 AIOC 的 udev 规则（2.5 节），让 Asterisk 能打开 HID。
  3. 允许 AIOC 的 USB ID：
    ; /etc/asterisk/res_usbradio.conf
[general]
usb_devices = 1209:7388    ; AIOC (all in one cable)
    （另一种做法：用 ./aioc-util.py --set-usb 0x0d8c 0x000c --store 把 AIOC 伪装成 C-Media CM108。之后再配置它时需要加 --open-usb 0x0d8c 0x000c。）
  4. 设置虚拟 COS（根据接收音频判断静噪）的保持时间。时间寄存器以 1/16 毫秒计：数值 = 毫秒 × 16 （由固件默认值和 G1LRO 的脚本确认，1500 毫秒 = 0x5DC0）。 官方 + 社区
    ./aioc-util.py --vcos-timctrl 24000 --store      # 1500 毫秒保持时间（G1LRO 的推荐值）
    （aioc-util README 中的示例 --vcos-timctrl 1500 只有约 94 毫秒。） 如果说话时字与字之间断掉，就调大。 如果 COS 被噪声打开，就提高阈值（--vcos-lvlctrl，默认 256）。G1LRO 建议噪声大的电台把阈值设在 1500 左右。 确保信道空闲时电台的 静噪是关闭的。VCOS 根据音频电平打开。 更好的办法：硬件 COS。 rev 1.2 或 G1LRO 双 COS 板可以读取电台真实的静噪状态：./aioc-util.py --enable-hwcos --store。 省事的办法 社区 ：G1LRO 的脚本会帮你完成第 3–6 步（它会修改 res_usbradio.conf、simpleusb.conf 和 rpt.conf，并先做备份）：
    wget -O customize.sh https://raw.githubusercontent.com/G1LRO/AIOC-ASL3-Config/main/customize.sh
sudo bash customize.sh
  5. 在 asl-menu 中 官方示例 ：
    • 设备类型：usbradio（菜单 2 > A1 > N4 > I2）（或 simpleusb，手台节点用它也很好）
    • 双工类型：1（菜单 2 > A1 > N5）
  6. 编辑 usbradio.conf（菜单 6 > H）。官方示例针对普星 PX-888，作为大多数手台的起点都合适：
    rxboost = 0
rxsqhyst = 500
carrierfrom = usbinvert
ctcssfrom = no
rxdemod = speaker
txprelim = no
invertptt = no
    （simpleusb.conf 中对应的是 carrierfrom = usbinvert、ctcssfrom = no。） 社区 G1LRO 给出的 simpleusb-tune-menu 设置： I = PTT 模式（他的旧教程中为 active LOW），J = COS 来源 usbinvert（VCOS）或 usb（高电平有效；他的新教程在硬件 COS 时用这个），L = CTCSS 来源 no。 COS 一直打开： 在 usb 和 usbinvert 之间切换，或提高 VCOS 阈值。COS 一直不打开： 切换两者，或降低阈值。
  7. 运行 radio-tune-menu（usbradio）或 simpleusb-tune-menu（simpleusb）设置收发电平：V 检查 COS，e 做回声测试，2/3 调电平，W 保存。然后重启 Asterisk：sudo systemctl restart asterisk。
  8. 用鹦鹉节点（Hubnet Parrot 40894）测试，或连接一个枢纽节点。用 小功率，天线和电脑分开放：射频窜入 USB 线是最常见的问题（第 8 节）。

#EchoLink（Windows，Sysop 模式）

常规

  • Tools → Sysop Settings → RX Ctrl：VOX（调整阈值）。AIOC 不支持通过串口提供 COS，所以一般用 VOX。

#5.18 车台 / 短波电台（把 AIOC 接到数据口或话筒口）

社区 AIOC 本质上就是一块集成了 USB 声卡、串口和 PTT 的小板，所以有动手能力的用户会把它接到其他电台上：

  • 从焊盘或尾线上的 K1 插座引出信号：送往电台的音频、来自电台的音频、PTT、UART TX/RX 和地（引脚定义见 AIOC README）。

  • 艾可慕 Icom 的 CI-V（单线总线）不加额外电路 无法 工作（GitHub #109，尚未解决）。

#6. PTT 故障排查流程

软件已经“按下发射”，但电台没有发射？
│
├─ 1. 插头插到底了吗？电台开机了吗？VOX 关了吗？没有锁键？不是禁止发射的信道？
│      快速硬件测试：AIOC Toolkit → Configure → Manual PTT State → PTT 1 ON。
│      如果这里电台能发射，说明线没问题，问题出在软件的 PTT 设置上。
│
├─ 2. 软件支持 CM108 PTT 吗？→ 用它（Linux：检查 /dev/hidraw 权限，见 2.5 节）
│
├─ 3. 使用 COM 口 PTT 时：
│     ├─ 软件设为 "DTR"（RTS 关闭）？→ 默认设置就应该能用。
│     ├─ 软件同时拉高 DTR 和 RTS，或 RTS 一直为高（Linux 上常见，打开端口时两根线都会拉高）
│     │      → aioc-util --ptt1 "CM108GPIO3|SERIALDTR" --store
│     ├─ 软件只用 RTS 发射
│     │      → aioc-util --ptt1 "CM108GPIO3|SERIALRTS" --store
│     └─ VARA FM → 设置 "Pin: DTR only"
│
├─ 4. 软件完全没有 PTT（APRSdroid、部分 Mac 软件）
│      → aioc-util --ptt1 "VPTT|CM108GPIO3|SERIALDTRNRTS" --store
│
└─ 5. 电台能发射，但松不开 / 写频时也会发射
       → 你把 PTT 改成了 SERIALDTR/SERIALRTS：写频前恢复默认：
         aioc-util --defaults --store
       → 检查发射音频是否误触发 VPTT（系统声音、VPTT 阈值太低）

⚠️ 给 AI 助手的提醒： 把 PTT 改为单独的 SERIALDTR 或 SERIALRTS 后，CHIRP 写频时电台可能会发射，因为 CHIRP 会切换这两根线。请让用户在写频前用 --defaults --store 恢复默认，或者专门留一个 AIOC 用于写频。

#9.2 升级已是 ≥ 1.2.0 的固件（不用拆壳） 官方

dfu-util -d 1209:7388 -a 0 -s 0x08000000:leave -D aioc-fw-1.4.1.bin

AIOC 会自动重启进入引导程序、刷写，然后自行重启。

  • Linux/macOS： 安装 dfu-util（apt install dfu-util / brew install dfu-util）。可能需要 sudo 或加入 plugdev 组。
  • Windows： dfu-util 需要给 DFU 接口安装 libusb/WinUSB 驱动。用 Zadig 给 AIOC 的 DFU 接口 /“STM32 BOOTLOADER”设备安装 WinUSB。（参见 AIOC README 中链接的教程：yeswolf.github.io/dfu。） 社区 Windows 11 上的 dfu-util 经常卡住或报 LIBUSB_ERROR_NOT_SUPPORTED（GitHub #28）。最简单的办法：用浏览器里的 AIOC Toolkit（见下文），或换一台 Linux 电脑或树莓派。
  • 用 AIOC Toolkit 在浏览器中刷写（最简单，尤其适合 Windows） 工具文档 ：
    1. 在 https://g1lro.github.io/aioc-toolkit/ → Flash Firmware 选项卡的 Latest Firmware 框里，通过 Download Firmware 链接下载 .bin。浏览器不能直接读取 GitHub 发布的文件，所以要先保存文件再选择它。
    2. 先让 AIOC 进入引导模式（9.3 第 1 步：短接排针最外侧的两个针脚，再插上 USB）。Toolkit 不会自己切换模式，AIOC 处于普通“DFU 运行时”模式时会阻止刷写。进入引导模式后它显示为 0483:df11。
    3. 连接，查看 Device Status，选择文件，点击 Flash Firmware 开始刷写并观察 Log。完成后去掉短接，重新插拔。 只刷官方的 aioc-fw-x.y.z.bin 文件。刷写失败可以重复以上步骤恢复。
  • 另一个浏览器刷写工具（原版 WebDFU） 社区, G1LRO 教程采用 ：AIOC 处于引导模式时，打开 https://devanlai.github.io/webdfu/dfu-util/ → Connect → 选择 STM32 Bootloader → Internal Flash → 选择 .bin → Download。

#9.3 首次刷写 / 救砖 官方

  1. 短接电路板编程排针最外侧的两个针脚（这是 BOOT 模式）。
  2. 插上 USB-C。设备显示为 STM32 引导程序。
  3. dfu-util -a 0 -s 0x08000000:leave -D aioc-fw-x.y.z.bin
  4. 去掉短接，拔下再插上。

任何升级之后：重新应用你的 aioc-util 设置（它们会被清除）。

#9.4 怎么知道我的固件版本？

USB 描述符里不报告固件版本。实用的判断方法：

  • aioc-util 或 AIOC Toolkit 能连上 → ≥ 1.3.0。能读出音频设置 / 猎狐设置 → ≥ 1.4.0。
  • 不确定的话，直接刷最新版（9.2）。这是解决大多数问题的推荐做法。

#10. 常见问题（供 AI 助手直接使用）

问：需要装驱动吗？ 不需要。Windows 10/11、Linux 和 macOS 都用系统自带的 USB 音频和 CDC 串口驱动。只有在 Windows 上升级固件时才需要 WinUSB 驱动（Zadig）。

问：哪个 COM 口是它？ 在设备管理器 → 端口 中观察，拔下 AIOC 再插上，新出现的 COMx 就是 AIOC。Linux：/dev/ttyACM0（装了 udev 规则后也可用 /dev/aioc）。macOS：/dev/cu.usbmodem…。

问：写频和数字模式能用同一根线吗？ 可以。串口负责写频，声卡负责数字模式。只是不要让两个软件同时占用同一个 COM 口。

问：能用在车台/基地台上吗？ 只有电台带 K1 类接口，或用转接线接到它的数据口/话筒口才行。在硬件 rev 1.2 上，线路电平输入请开启 --audio-tx-boost on，线路电平输出请调高接收增益。

问：能在树莓派上用吗？ 能。Direwolf、AllStarLink 3、SvxLink、Pat、QtSoundModem 和 LinBPQ 都能在树莓派 OS 上运行。使用 CM108 PTT 和 udev 规则。

问：能用 iPhone/iPad 吗？ 部分可以。iOS 只把 AIOC 识别为声卡。RadioMail（Winlink）和 Packet Commander 已在 AIOC 固件 1.4.1 + 开启 虚拟 PTT 的情况下验证可用（5.16 节）。在 iOS 上无法用 CHIRP 写频，也无法使用串口或 CM108 PTT。

问：能用电脑通话（语音）吗？ 能。在 VoIP 或联网应用（AllStarLink、SvxLink、EchoLink、Mumble 桥接）里把 AIOC 选为麦克风/扬声器即可。语音 PTT 需要 CM108/串口控制或 VPTT。

问：我的电台有两个 PTT（双段手台）？ PTT1 默认是 CM108 GPIO3/串口，PTT2 是 CM108 GPIO4。用 --swap-ptt 或 --ptt2 修改。

问：支持 9600 波特分组吗？ 通过 K1 接口不支持（音频经过滤波）。请用 1200 波特 AFSK 或 VARA FM 窄带。
